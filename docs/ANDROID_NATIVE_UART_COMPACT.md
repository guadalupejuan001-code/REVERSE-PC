The native C27 continuation can receive a bounded external serial input file through REVERSE_PC_UART_INPUT_FILE. It feeds the existing MinimalGuest console_input operation after authenticating and exactly round-tripping the source, before the next CPU instruction. It does not interpret shell commands on the host.

The file contains at most 4096 bytes, including binary bytes. An unset environment variable and an empty input file have identical behavior to the existing continuation. Missing files are rejected before guest execution. A nonempty input receipt records the exact SHA-256, length, instruction count and counter phase in report provenance. The normal modeled PL011 queue and its existing IRQ handling deliver the bytes to the guest.

RVG/MXIM encoding, the original decoder, XI/Ether state authority, logical RAM, disk, seed, counter cadence and all Android acceptance checks are unchanged. Introducing input does not attest Android boot. SystemServer, live PID1 boot completion, enforcing SELinux and the real display remain required.

The motivating diagnostic is a genuine pre-SystemServer wait on the ART GC complete condition variable. Console queries permit inspecting Android from inside the running guest. Any later operating-system adjustment must be recorded as an external input event; no priority or boot-property value is changed by enabling this transport.
