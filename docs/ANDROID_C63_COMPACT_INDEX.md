A 100-million-instruction statistical profile puts 28.95% of sampled host execution in AdaptiveOverrideMap::get, 12.80% in access resolution, and only 3.77% in SIMD instruction execution. The profiling harness enables sampling around execution and disables it during journal publication; mcount call hooks are replaced with NOPs. Its complete original checkpoint matches the unprofiled reference. Optimize the measured dictionary lookup rather than changing guest crypto behavior or CPU features.

The opt-in REVERSE_PC_COMPACT_INDEX_LOOKASIDE=1 profile keeps sixteen borrowed page lookup results per host thread, including absent pages. No byte values or quantum projections are cached. Every hit still asks the original authoritative Page for its current presence/value. Each State has a unique, saturating lifetime identity. Dictionary insertion/removal and Page pointer replacement advance an epoch. Copy-on-write creates a new State identity. Identity/epoch exhaustion disables the optimization, avoiding reuse and stale pointers. Dense promotion/demotion and in-place byte assignment keep using the same Page, so current values remain authoritative. Cross-thread handoff sees structural epoch changes through the existing synchronization of the caller. Lookups do not introduce support for concurrent mutation of one previously unsynchronized memory object.

Metadata is approximately 512 bytes per host thread plus sixteen bytes per State. It is never serialized. Original sparse/dense thresholds, page masks, arbitrary-precision addresses, background rules, revision/quota behavior, quantum bindings and copy-on-write behavior retain their meaning. CMake defaults to the original behavior; the profile can be explicitly enabled with -DREVERSE_PC_COMPACT_INDEX_LOOKASIDE=ON. Direct native builds use the corresponding compiler definition with value 1. C61's numeric store profile is retained.

The compact RVG/MXIM encoder and decoder are unchanged. MXIM3 still hex-encodes its page masks/values inside the original RVG wrapper. This optimization does not change that representation or its expansion ratio, add flat guest RAM, or create another memory authority. Logical RAM remains 2 GiB. All CPU instructions, clock/IRQ handling, original disk authentication, completed-boot requirements and the original C53 frame decoder remain unchanged.

Local validation passes 51,633 focused lifetime/invalidation checks under Release and ASan+UBSan: negative lookup then insertion, sparse/dense transitions, assignment, full deletion/reinsertion, COW snapshots, repeated allocator/address reuse, imported page records, UINT64_MAX, cross-thread handoff and unchanged encoded page records.
